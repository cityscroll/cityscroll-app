crol-list.org · Single Redirect

Redirect direct site visitors, not the CityScroll mirror.

Cloudflare dashboard › Websites › crol-list.org › Rules › Overview › Create rule › Redirect Rule
Rule nameRedirect public crol-list.org site to CityScroll
Match typeCustom filter expression
Expression(http.host in {"crol-list.org" "www.crol-list.org"} and cf.worker.upstream_zone eq "")
Redirect typeDynamic
Target expressionconcat("https://cityscroll.org", http.request.uri.path)
Status code301
Preserve queryOn

Select Deploy.

The exclusion is load-bearing. cf.worker.upstream_zone eq "" matches direct browser and crawler requests but excludes the CityScroll Worker’s origin subrequest. Without it, the mirror would loop.
  • ✓The host match covers only crol-list.org and www.crol-list.org. API subdomains and email delivery are not redirected.
  • ✓The target expression keeps the original path; Preserve query string keeps the query.
  • ✓Fragments such as #notice/… never reach the server. Because the redirect supplies no new fragment, conforming browsers retain the original one client-side.

cityscroll.org · Pages custom domain

Attach beta through Pages before touching DNS.

Cloudflare dashboard › Workers & Pages › crol-list-beta › Custom domains › Set up a domain
Custom domainbeta.cityscroll.org
Pages projectcrol-list-beta
Pages targetcrol-list-beta.pages.dev

Select Continue, review the DNS change, and confirm activation. Because cityscroll.org is already managed by the same Cloudflare account, Pages should create the DNS record automatically.

If Cloudflare asks for the DNS record: approve a CNAME named beta targeting crol-list-beta.pages.dev, with Proxy status: Proxied and TTL: Auto.
Do not create the CNAME first in DNS. Cloudflare documents that a manually created Pages CNAME without the Pages custom-domain association can return a 522. If a beta record already exists, return to the Pages custom-domain flow and let it validate or replace that record—do not create a duplicate.
